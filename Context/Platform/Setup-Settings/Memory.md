## Facts
<!-- Stable, verified knowledge. One bullet per fact. Tagged. -->

- There is no config file: all runtime settings live in the `app_settings` table in `data/firm.db`, managed from the web UI. (General)
- First run redirects to `/setup`, a wizard served by the app itself; later changes go through Settings in the navigation bar. (General)
- Wizard provider choices are OpenAI / OpenAI-compatible, Anthropic, Ollama and Offline, with a one-click toggle between local Ollama and online OpenCode; provider-specific fields appear only for the selected provider. (General)
- A custom base URL is needed for OpenRouter, vLLM, proxies, or a self-hosted Ollama. (General)
- The wizard can optionally import the context brief and one CV version immediately; more CV versions can be added later. (General)
- Stored configuration takes precedence over environment variables once the wizard is complete; env vars are intended for headless use, CI and tests. (General)
- API keys are stored only in `data/firm.db`, sent only to the selected provider, masked in the UI after saving, and never written to a `.env` file. (General)
- Security posture: binds `127.0.0.1` by default, no telemetry, no analytics, no external asset CDNs; data at rest is otherwise unencrypted, so use full-disk encryption and back up `data/`. (General)
- Single-user by design: no authentication or multi-tenant isolation, so the server must not be exposed to untrusted networks. (General)

## Gotchas
