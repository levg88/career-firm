## Facts
- Career Firm is a local-first boutique career firm run by agents; it imports a context brief and CV versions once, then tailors an ATS-safe PDF + DOCX for each job description. (General)
- The firm has three agents: Office Manager (extracts a faithful structured record), Headhunter (decodes a posting, maps evidence, scores the match), and Resume Writer (selects/reorders/rephrases only supported content and renders documents). (General)
- The codebase is TypeScript on Node.js 20+, Express 5, EJS views, SQLite via better-sqlite3, pdfkit/pdf-lib, and docx/mammoth. (General)
- Top-level layout: `src/` is application source; `src/agents/` the firm agents; `src/llm/` provider adapters; `src/documents/` extraction and rendering; `src/api/` Express routes; `src/orchestrator/` the end-to-end workflow; `views/` EJS templates; `tests/` Vitest suites. (General)
- Runtime data lives under `data/` (ignored by git): `firm.db`, uploaded context/CVs, generated documents, and run workspaces. (General)
- The knowledge in this base covers firm agents, LLM providers, CV/job handling, PDF/DOCX rendering, local SQLite storage, setup and CLI operations. (General)

## Gotchas
- A provider being selected does not mean it is available: a missing key or a failed model call degrades to deterministic offline behaviour behind a visible banner instead of crashing. (General)
- Truthfulness is a hard boundary: the Resume Writer may select and rephrase source material, but employers, titles, dates, degrees, metrics, email, and phone must come from the CV/context. The grounding validator flags violations. (General)
- LinkedIn is deliberately not logged into or scraped; only CV files and a user-exported LinkedIn PDF are imported. (General)
- `data/` is gitignored. Do not commit `firm.db`, generated PDFs/DOCX, uploads, or run artifacts. (General)
